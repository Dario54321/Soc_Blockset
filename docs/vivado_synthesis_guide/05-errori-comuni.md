# 5. Errori comuni — riferimento rapido

Tabella pensata per essere consultata al volo quando qualcosa si blocca. Per ciascuno: il messaggio esatto, perché succede (causa reale, non sintomo), e il fix, con rimando al capitolo che spiega il concetto per esteso.

| Messaggio (o sua parte distintiva) | Causa reale | Fix | Approfondimento |
|---|---|---|---|
| `HDL code generation is not directly supported for a MATLAB Function Block. This object must be enclosed within a subsystem.` | Il DUT passato a `checkhdl`/`makehdl` è un blocco MATLAB Function a livello root, non incapsulato | Incapsula il blocco in un Subsystem con `Simulink.BlockDiagram.createSubsystem(handle, 'Name', ...)` — handle **numerico**, non stringa | Capitolo 2 |
| `CELL2MAT does not support cell arrays containing cell arrays or objects` (dentro `createSubsystemImpl`) | Passato un path stringa (dentro una cell array) a `Simulink.BlockDiagram.createSubsystem` invece di un handle numerico | Usa `get_param(blocco,'Handle')` per ottenere il numero, poi passalo direttamente (non in una cell array) | Capitolo 2 |
| `The model contains "Double" type signals. To generate synthesizable HDL code, either select the "Use Floating Point" check box or change the "Double" type signals to fixed-point data type.` | Segnali `double` in una regione che genera HDL — un vero calcolo aritmetico in virgola mobile non è sintetizzabile senza supporto dedicato | `hdlset_param(mdl,'UseFloatingPoint','on')` (via più rapida, non richiede riprogettare i tipi) oppure converti i segnali a fixed-point dall'ingresso (via più leggera in risorse, richiede analisi di quantizzazione) | Capitolo 2 |
| `Property 'UseFloatingPoint' does not exist` | Tentato `set_param(configSet,'UseFloatingPoint','on')` — parametro HDL Coder non accessibile con `set_param` generico | Usa `hdlset_param(mdl,'UseFloatingPoint','on')`, funzione dedicata ai parametri HDL Coder | Capitolo 2 |
| `Unable to use 'NomeScelto' as a new referenced model name. The model 'NomeScelto' already exists on the path.` (pur non avendo creato nulla con quel nome) | Il nome scelto per un nuovo Model Reference collide con una funzione MATLAB toolbox già esistente sul path (es. `'FPGA'` collide con `fpga.m`) | Scegli un nome diverso (es. aggiungi un suffisso, tipo `FPGA_HW` invece di `FPGA`) | Capitolo 1 |
| `ERROR: [Place 30-99] Placer failed with error: 'IO Clock Placer failed'` / centinaia di `Instance ..._OBUF[...] is not placed` / `Bonded IOB N/200 (>100%)` | Sintesi/Implementation SENZA `-mode out_of_context` su un blocco con bus larghi come porte top-level — Vivado tenta di assegnare ogni bit a un pin fisico reale, e il package non ne ha abbastanza | Aggiungi `-mode out_of_context` a `synth_design` per la sola sintesi (stima area); per un'Implementation completa serve un DUT con porte strette, non bus larghi | Capitolo 3 |
| `ERROR: [Place 30-494] The design is empty` (con `-mode out_of_context`, durante Implementation) | Senza un vero contesto/board a cui collegarsi, Vivado ottimizza via tutta la logica non osservata durante l'Implementation completa | Non tentare Implementation completa su un blocco isolato con `out_of_context` — limitati a `report_utilization` dalla sola sintesi, oppure integra il blocco nel design di sistema completo per un'Implementation realistica | Capitolo 3 |
| `report_timing -unconstrained` non riconosciuto/non valido | Opzione non esistente in Vivado 2022.1 | Usa la tecnica del clock virtuale (`create_clock` + `set_input_delay`/`set_output_delay` a 0) | Capitolo 3 |
| Comandi Tcl/Vivado o script MATLAB falliscono in modo strano su percorsi tipo `C:\Users\Nome Cognome\...` | Path con spazi — bug noto sia di Vivado sia di alcuni strumenti MATLAB (es. `socModelBuilder`, alcuni comandi HDL Coder) | Lavora sempre su un percorso senza spazi (es. `D:\NomeCartella\`), sia per il modello sia per gli output generati | — |
| `checkhdl` non lancia nessun errore MATLAB anche se il report segnala errori | Comportamento normale di `checkhdl`: scrive un report HTML e stampa il conteggio in console, ma non solleva un'eccezione MATLAB intercettabile con `try/catch` | Leggi sempre il conteggio "N errors" stampato in console (o apri il report HTML) prima di procedere a `makehdl` | Capitolo 2 |

## Per gli errori specifici del validatore `socModelBuilder`/SoC Builder

Questa guida copre il percorso **diretto** (HDL Coder + Vivado, bypassando SoC Builder). Se invece stai usando `socModelBuilder`/`buildModel`/l'app SoC Builder e incontri errori come `"Unrecognized field name 'bit_file'"`, `"Register port ... must be connected to a DUT"`, o problemi di toolchain ARM, quelli sono documentati separatamente in [`../socbuilder_notes.md`](../socbuilder_notes.md) — un validatore diverso, con regole diverse da quelle di HDL Coder/Vivado descritte qui.
